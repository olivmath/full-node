Lunes Node — Mandarin

Full Node da blockchain Lunes. Conecta, armazena, valida e propaga blocos da rede.

Scala 2.12 sbt v0.0.10 Apache 2.0

Organizacao

io.lunes — dominio Lunes. Framework base herdado do scorex.

Coin

Nome: LUNES (LNS)
Supply inicial: 15.072.853.761.500.800 units

Consenso

NXT-like Proof of Stake com suporte a microblocks (NG protocol)

Entrypoint

O ponto de entrada e io.lunes.LunesNode.main() em src/main/scala/io/lunes/LunesNode.scala.

Fluxo de inicializacao

PassoO que fazArquivo
1Corrige NTP, instala SLF4J bridgeLunesNode.main()
2Le lunesnode.conf ou path do argreadConfig()
3Inicia Kamon + MetricsMetrics.start()
4Cria ActorSystem via RootActorSystemroot/RootActorSystem.scala
5Seta AddressScheme (chain ID)scorex/account/AddressScheme.scala
6Instancia LunesNode e chama .run()LunesNode.scala:582

Dentro de run()

Valida genesis block, abre wallet, inicia UTX pool, cria Miner, configura appenders (Block, Checkpoint, Extension, Microblock), sobe rede P2P via NetworkServer, inicia REST API completa, e agenda mineracao.

Rede P2P

Baseada em Netty. O node descobre peers, faz handshake, troca blocos, scores e transacoes via protocolo binario.

ArquivoResponsabilidade

Handshake.scalaProtocolo de handshake (app name, version, nonce)
HandshakeHandler.scalaValida handshake, aceita/rejeita peer
PeerDatabase.scalaArmazena peers conhecidos e blacklist
RxExtensionLoader.scalaCarrega extensoes (forks) de peers via Rx
RxScoreObserver.scalaObserva scores de peers para sync
MicroBlockSynchronizer.scalaSincroniza microblocks entre peers
UtxPoolSynchronizer.scalaPropaga transacoes nao confirmadas
HistoryReplier.scalaResponde a pedidos de blocos/signatures
UPnP.scalaConfiguracao automatica de port forwarding
TrafficLogger.scalaLog de mensagens de rede (filtravel)

Portas padrao

P2P: 5550 • REST API: 5555

Consenso (NXT PoS)

Usa NXT-like Proof of Stake com NG (Next-Generation) protocol para microblocks. O calculo de geracao esta em PoSCalc.scala.

NxtConsensusBlockField.scalaCampo de consenso serializado no bloco
NxtLikeConsensusBlockData.scalaBase target + generation signature
Block.scalaEstrutura do bloco (header + TXs)
MicroBlock.scalaMicrobloco do protocolo NG

Validacao & Diffs

Cada tipo tem seu diff em state2/diffs/. A validacao comum (timestamps, fees, signatures) esta em CommonValidation.scala e Verifier.scala.

State & Storage

O state e gerenciado por BlockchainUpdaterImpl com suporte a NG (microblocks pendentes via NgState). Persistencia em LevelDB.

ComponenteArquivoPapel
UpdaterBlockchainUpdaterImpl.scalaOrquestra append/rollback de blocos
State Readerreader/StateReaderImpl.scalaLeitura de balances, assets, leases
Composite Readerreader/CompositeStateReader.scalaCombina state persistido + diff pendente
DiffDiff.scalaDelta de state (portfolios, aliases, assets)
PortfolioPortfolio.scalaBalance + lease info + assets de uma conta
StorageStateStorage.scalaCamada de acesso ao LevelDB
HistoryHistoryWriterImpl.scalaPersiste block headers e scores
LevelDBcore/storage/db/Abstraccoes de storage (codecs, versioning)

Appenders

Em state2/appender/: BlockAppender, ExtensionAppender (forks), MicroblockAppender, CheckpointAppender. Cada um valida e aplica diffs ao state.

Mineracao

Implementada em mining/Miner.scala. O miner agenda tentativas de gerar blocos baseado no PoS e, quando bem-sucedido, gera key blocks e microblocks.

ArquivoPapel
Miner.scalaTrait + MinerImpl: agenda e executa mineracao
MiningConstraint.scalaLimites de TXs por bloco/microbloco
Estimator.scalaEstimativa de tamanho de TX para constraints

Parametros (config)

miner {
  quorum = 1                           # conexoes minimas
  micro-block-interval = 5s
  max-transactions-in-key-block = 0    # key block vazio (NG)
  max-transactions-in-micro-block = 255
  min-micro-block-age = 6s
}

REST API

Construida com Akka HTTP + Swagger. Bind padrao em 127.0.0.1:5555. Autenticacao via header X-API-Key (hash armazenado em config).

rest-api {
  bind-address = "127.0.0.1"
  port = 5555
  api-key-hash = "3XyBSS9..."
  cors = yes
}

Swagger UI embutido em src/main/resources/swagger-ui/.

Configuracao

Dois niveis de config: lunesnode.conf (minimo, usuario edita) e application.conf (completo, defaults do sistema).

Config minimo (lunesnode.conf)

lunes {
  directory = "./"
  blockchain.type = ""         # MAINNET ou TESTNET
  network.known-peers = [""]   # ip:port de um node
  wallet.password = ""
  wallet.seed = ""             # seed em BASE58
}

Docker

Compose com dois servicos: master_node (IP fixo 172.0.0.5, porta 80→5555) e node (IP 172.0.0.10, porta 81→5555). Rede customizada 172.0.0.0/16.

# Subir a rede local
docker-compose -f docker/docker-compose.yml up -d

# Logs do master
docker-compose -f docker/docker-compose.yml logs -f master_node

Build & Run

Pre-requisitos

  • JDK 11
  • sbt

Comandos

# Compilar
sbt compile

# Testes
sbt test

# Gerar fat JAR
sbt assembly
# → target/scala-2.12/lunesnode-0.0.10.jar

# Rodar
sbt run

# Rodar com config customizado
java -jar target/scala-2.12/lunesnode-0.0.10.jar /path/to/lunesnode.conf

# Build para rede especifica
sbt -Dnetwork=testnet assembly
sbt -Dnetwork=mainnet assembly
